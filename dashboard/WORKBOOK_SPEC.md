# Dashboard specification

`index.html` is the deliverable, generated by `build_dashboard.py` from the
`control_*.csv` exports in this directory. This file specifies the same page for
anyone who wants to rebuild it in Tableau by hand.

## Why HTML rather than a Tableau workbook

The original plan named a published `.twbx` as the deliverable. It was replaced
deliberately, and the reasoning is the point rather than the convenience:

- A `.twbx` is binary. It cannot be reviewed in a diff, so a number changing
  inside it is invisible to code review.
- It cannot be regenerated by code. Reproducing it means a person repeating a
  sequence of clicks, and the record of what they clicked lives nowhere.
- It fails silently. When a CSV falls out of sync the workbook keeps rendering
  whatever it cached.

`build_dashboard.py` inverts all three. It raises `MissingControlFile` when an
export is absent, its output is a text diff, and regenerating it is one command.
That matters more here than interactive filtering, because every finding on the
page is a fixed statement about a closed launch window.

## Regenerating

```bash
cd pawtrail_dbt && ../.venv/bin/python -c "
import duckdb
c = duckdb.connect('pawtrail.duckdb', read_only=True)
c.sql('''select metric_name, decision_question, current_value, segment, threshold_value,
                threshold_direction, status, action, owner
         from main.fct_decision_contract
         order by case status when 'triggered' then 0 when 'ok' then 1 else 2 end,
                  metric_name''').write_csv('../dashboard/control_decision_contract.csv')
"
cd .. && .venv/bin/python -c "
from pathlib import Path
from dashboard.build_dashboard import build_dashboard
build_dashboard(Path('dashboard'), Path('dashboard/index.html'))
"
```

Re-running it twice must produce no diff. If it does, an export is
non-deterministic — check that every `mf query` carries `--order`.

## Structure: four decision questions

The page is organised around the four questions a launch review actually asks,
not around the models that happen to exist.

| Band | Question | Cards | Source |
|---|---|---|---|
| 1 | Is it growing? | Cumulative attach rate + weekly series | `control_attach_rate.csv` |
| 2 | Are they staying? | Base never rebilled, cycle-exposure distribution, and the void cards | `control_base_never_rebilled.csv`, `control_cycle_exposure.csv` |
| 3 | Is it valuable? | Cycles to breakeven per channel | `control_breakeven_by_channel.csv` |
| 4 | Is it efficient? | Effective CAC per channel, decision contract table | `control_effective_cac.csv`, `control_decision_contract.csv` |

Chart types are deliberately plain: a stat card with one figure and one
subordinate figure, and a scrollable table behind a disclosure. Nothing on the
page needs a chart type a reader has to learn.

## The void convention

Band 2 is mostly **void cards** — a titled card stating a metric that cannot be
computed, what it is blocked on, and which phase unblocks it. Five of them carry
"not observable" and a `PHASE 2` badge.

This is the page's most important convention and the easiest to get wrong. A
dashboard that silently omits rebill rate and NRR looks complete; one that names
them as absent tells the reader what the analysis does *not* know. Anyone
rebuilding this in Tableau must reproduce the void cards, not drop them because
they have no data behind them.

Band 2 does carry one real number — `pct_base_never_rebilled`, read **ungrouped**
— which turns "churn is out of scope" from a caveat into a computed fact. Read it
at any other grain and it is wrong: grouped by `cycle_exposure_cohort` the
numerator is its own denominator inside cohort `'0'` and the card reads 100%.

## The decision contract table

Every row is a metric, its current value, the segment that value came from, a
threshold set *before* the value was observed, a status, an owner and an action.

Two rules govern it:

- **The segment column is not decoration.** A categorical threshold is written to
  catch the worst state or channel, so a row reading `kit_lost_rate 0.072,
  triggered, audit the carrier` is not actionable until it also says `OH`.
- **Thresholds are never tuned to fit the data.** If a metric does not trigger,
  the finding is the metric. A threshold moved to fit an observation cannot
  afterwards be evidence about that observation.
